01 / Analogy

AWS 용어, 실생활 비유로 이해하기

 

데이터 파이프라인 전체를 스마트 공장에 비유하면 모든 서비스가 한번에 보인다.

전체 구조 비유 🏭

AWS 데이터 파이프라인 = 대형 스마트 공장

원재료(Raw Data)가 입구로 들어오면 → 컨베이어 벨트(Kinesis)로 이동 → 가공 공장(Glue/EMR)에서 변환 → 창고(S3, Redshift)에 보관 → 분석실(QuickSight/Athena)에서 인사이트 추출. 공장 전체를 보안 팀(IAM/KMS)이 지키고, 공장장(CloudWatch)이 모니터링한다.

Domain 1 📥 데이터 수집 / 스트리밍
🔄
Amazon Kinesis Data Streams
실시간 컨베이어 벨트

공장 입구의 컨베이어 벨트. 데이터가 끊임없이 올라온다. 원하는 위치(샤드)에 여러 작업자가 동시 처리. 24시간~7일 보관.

🚛
Kinesis Data Firehose
자동 배달 트럭

목적지(S3/Redshift)로 자동 배달해주는 트럭. 운전자(개발자) 없어도 OK. 단, 실시간이 아닌 소량씩 묶어서 배달(Micro-batch).

🧮
Kinesis Data Analytics
실시간 계산기

벨트 위 즉석 계산기. 지나가는 데이터를 SQL/Flink로 실시간 분석. "불량률 5% 초과 시 즉시 알람!"

📬
Amazon SQS
대기표 번호기

은행 번호표 뽑는 기계. 손님(메시지)이 몰려도 줄 세워 순서대로 처리. 최대 14일 보관. 1:1 비동기 통신.

📢
Amazon SNS
교내 방송 시스템

방송실에서 전체 방송 한 번 누르면 구독한 모든 채널(SQS, Lambda, Email)에 동시 전달. 1:N 팬아웃.

📅
Amazon EventBridge
스마트 일정 비서

이벤트(파일 업로드, DB 변경)를 감지해서 자동으로 관련 서비스에 전달. "S3에 파일 올라오면 Lambda 자동 실행."

🚚
AWS DMS
이삿짐 센터

Oracle → Aurora 이사 때 부르는 전문 이사 업체. 이사 중에도 기존 DB 사용 가능(CDC). 이기종 DB 호환 지원.

📦
AWS Snowball Edge
데이터 이사 박스

인터넷 느릴 때 물리적 하드드라이브 박스를 택배로 받아 데이터 채운 뒤 보내면 S3에 자동 업로드.

Domain 1 ⚙️ 데이터 변환 / 처리
🧵
AWS Glue
자동 번역 공장 직원

CSV/JSON을 자동으로 Parquet으로 변환. Crawler = 재료 파악, Job = 가공, Catalog = 목록 관리. 서버리스.

👨‍🍳
AWS Glue DataBrew
요리 레시피 앱

코딩 없이 드래그앤드롭으로 데이터 정제. "중복 제거", "결측치 채우기" 버튼으로 처리. 분석가 직접 사용 가능.

🏭
Amazon EMR
대형 공장 클러스터

Spark/Hive/Hadoop을 돌리는 대형 제조 공장. 서버 수백 대 대규모 배치 처리. 작업 끝나면 공장 해체 → 비용 절감.

⚡
AWS Lambda
호출 시 출근하는 알바

평소엔 대기, 이벤트 발생 시 즉시 출근해서 15분 내 처리하고 퇴근. 서버 관리 0. 소량·짧은 처리에 최적.

🔄
Amazon MWAA (Airflow)
공정 흐름도 관리자

공정의 순서·의존성 관리. "A 완료 → B 시작 → C·D 동시 → E 마무리". DAG로 복잡한 파이프라인 스케줄링.

🗂️
AWS Glue Data Catalog
공장 자재 목록부

어디에 어떤 자재가 있는지 메타데이터 목록. Athena, EMR, Redshift Spectrum이 이 목록을 공유해서 사용.

Domain 2 🗄️ 데이터 저장
🏬
Amazon S3
무한 확장 창고

용량 무제한 초대형 창고. 어떤 파일이든 저장. Lifecycle으로 자주 안 쓰는 파일을 저렴한 냉동창고(Glacier)로 자동 이동.

🧊
S3 Glacier / Deep Archive
냉동 창고

거의 안 꺼낼 자료를 넣는 냉동 보관 창고. 꺼낼 때 해동 시간 필요(수분~12시간). 가격 매우 저렴. 규정 준수 보관.

🧩
Amazon DynamoDB
포스트잇 메모장

Key로 즉시 꺼내는 포스트잇. 어디서든 1ms 응답. 형식 자유(NoSQL). 복잡한 쿼리 불가. "userId → 사용자 정보 즉시 조회."

📊
Amazon Redshift
대형 분석 연구소

수십억 건 데이터를 컬럼 단위로 분석하는 연구소. 복잡한 집계 쿼리 고속 처리. OLAP 전용. DISTKEY·SORTKEY 설계가 성능 핵심.

🏥
Amazon RDS / Aurora
전자 의무 기록 시스템

정형화된 관계형 기록 관리. INSERT/UPDATE/SELECT 빠른 OLTP. Aurora = RDS 고성능 버전(5배 빠름). Multi-AZ 고가용성.

💨
Amazon ElastiCache
책상 위 포스트잇

자주 쓰는 걸 책상 위에 꺼내두기. DB까지 안 가도 메모리에서 즉시 응답(마이크로초). Redis = 기능 풍부, Memcached = 단순.

🏛️
AWS Lake Formation
데이터 창고 보안관

데이터 레이크의 출입증 관리자. "A팀은 고객 테이블만, B팀은 매출 컬럼만" 세밀한 접근 권한 설정. 중앙 거버넌스 제공.

⏱️
Amazon Timestream
시간표 일지 기록계

IoT 센서, 서버 메트릭처럼 시간순 데이터 전용 DB. 시계열 쿼리에 최적화. 자동 압축·TTL 관리. Grafana 연동.

Domain 2/3 📈 분석 / 쿼리
🔍
Amazon Athena
창고에서 바로 SQL 검색

S3 창고에 가서 직접 SQL 검색. 서버 없이 쿼리. 스캔 데이터 TB당 과금. Parquet + 파티셔닝으로 비용 90% 절감 가능.

📊
Amazon QuickSight
자동 인포그래픽 제작자

데이터 연결하면 자동으로 그래프·대시보드 생성. SPICE 엔진으로 빠른 응답. ML Insights로 이상치 자동 탐지. 임원 보고용.

🔭
Redshift Spectrum
창고-연구소 연결 통로

Redshift에서 S3 데이터를 이동 없이 직접 쿼리. 콜드 데이터 비용 효율적 분석. Glue Catalog와 연동해 사용.

🔎
Amazon OpenSearch
전문 검색 엔진

구글 같은 전문 검색 기능. 로그 검색, 텍스트 분석, 실시간 모니터링 대시보드. "오류 로그에서 특정 패턴 즉시 검색."

Domain 4 🔐 보안 / 거버넌스
🪪
AWS IAM
회사 출입증 + 직책 관리

누가 어디에 들어갈 수 있는지 정하는 HR 시스템. Role = 직책, Policy = 권한 문서, User = 직원. 최소 권한 원칙이 핵심.

🔑
AWS KMS
열쇠 보관 금고

암호화 키를 안전하게 보관하는 금고. SSE-KMS로 S3 암호화. CMK로 직접 통제. CloudTrail로 키 사용 이력 추적 가능.

🤐
AWS Secrets Manager
디지털 비밀 금고

DB 비밀번호, API Key를 코드에 직접 쓰지 않고 금고에 보관. 자동 순환(Rotation). 앱은 금고에서 꺼내 사용.

🕵️
Amazon Macie
개인정보 탐정

S3에서 주민번호·신용카드 같은 민감 데이터를 ML로 자동 탐지. GDPR 컴플라이언스 필수 도구. 탐지만, 삭제는 별도 처리.

📋
AWS CloudTrail
회사 CCTV

AWS 계정의 모든 API 호출 기록하는 CCTV. "누가 언제 S3 버킷 삭제했나?" 감사·포렌식 필수. CloudTrail vs Config 혼동 금지.

🌐
Amazon VPC
회사 사설 네트워크

AWS 내 나만의 사설 인터넷. VPC Endpoint로 인터넷 없이 S3·DynamoDB 직접 접근. 보안 + 데이터 전송 비용 이점.

Domain 3 🛠️ 운영 / 오케스트레이션
📡
Amazon CloudWatch
공장 계기판

서버·서비스 상태 모니터링 계기판. CPU/메모리/에러 수 확인. Alarm으로 임계치 초과 시 SNS 알림. Logs로 로그 수집·분석.

🤖
AWS Step Functions
공정 자동화 로봇팔

여러 Lambda를 순서대로 연결하는 로봇팔. "1단계 성공→2단계, 실패→재시도." 시각적 워크플로. MWAA보다 간단한 흐름에 적합.

📑
AWS Config
설정 변경 이력 장부

리소스 설정이 언제 어떻게 바뀌었는지 기록. 규정 준수 자동 체크. CloudTrail = "누가 뭘 했나", Config = "설정 변경 이력".

🧪
AWS Data Exchange
데이터 마켓플레이스

외부 업체 데이터를 구독·구매하는 마켓. 날씨, 금융, 의료 데이터 등을 API 없이 S3로 직접 수신. 서드파티 데이터 활용.

03 / Question Patterns

반복 출제 문제 유형 30가지 패턴

 

이 패턴들을 익히면 새로운 문제도 패턴 매칭으로 빠르게 풀린다.

PATTERN 01
실시간 vs 배치 서비스 선택

ms 단위 실시간 → KDS. 수분 단위 묶음 전송 → Firehose. 대규모 배치 → Glue/EMR. 서버리스 간단 처리 → Lambda.

KDS는 직접 소비자 코드 필요, Firehose는 완전 관리형 — 관리 부담 없으면 Firehose 선택
PATTERN 02
데이터 레이크 아키텍처 설계

항상 S3 + Glue Data Catalog + Lake Formation 조합. 쿼리엔 Athena, 거버넌스엔 Lake Formation.

데이터 레이크 = S3 기반. Lake Formation = 보안 관리자. Glue Catalog = 메타데이터 저장소
PATTERN 03
서버리스 ETL 파이프라인

서버 관리 없이 ETL → AWS Glue. 시각적 UI 필요 → Glue DataBrew. 대규모 커스텀 → EMR.

"완전 관리형" 키워드 등장 시 항상 Glue 우선 고려
PATTERN 04
이기종 DB 마이그레이션

동종 DB 이전 → DMS. 이기종(Oracle→Aurora) → SCT + DMS. 무중단 실시간 복제 → CDC 활성화.

SCT = 스키마 변환, DMS = 데이터 이동 — 역할 구분 암기 필수
PATTERN 05
스토리지 비용 최적화

자주 접근 → S3 Standard. 가끔 → S3 IA. 거의 없음 → Glacier. CSV → Parquet 전환 + 파티셔닝.

Athena는 스캔 데이터만큼 과금 → Parquet + 파티셔닝으로 최대 90% 절감 가능
PATTERN 06
데이터 암호화 방식 선택

AWS 관리 키 → SSE-S3. KMS 제어 → SSE-KMS. 고객 키 직접 제공 → SSE-C. 클라이언트 암호화 → CSE.

"규정 준수 감사 필요" → SSE-KMS. CloudTrail로 키 사용 이력 추적 가능
PATTERN 07
IAM 최소 권한 설계

항상 최소 권한 원칙. 리소스 기반 vs 자격증명 기반 정책 구분. Cross-Account → Role Assume.

Lambda/Glue에 권한 부여 시 User가 아닌 Role 사용 — 서비스는 Role로 인증
PATTERN 08
DynamoDB 성능 문제 해결

핫 파티션 → 파티션 키 분산 설계. 읽기 부하 → DAX 캐시. 갑작스런 트래픽 → On-Demand 모드.

파티션 키를 다양하게 분산해야 핫 파티션 방지 — S3 Prefix 분산과 같은 원리
PATTERN 09
Redshift 쿼리 최적화

DISTKEY → 조인 많은 컬럼. SORTKEY → WHERE절 조건 컬럼. COPY 명령으로 S3에서 병렬 로드.

INSERT보다 COPY가 훨씬 빠름 — S3에서 Redshift 적재 시 항상 COPY 사용
PATTERN 10
PII 민감 정보 탐지·처리

S3 자동 탐지 → Macie. ETL 내 PII 탐지·마스킹 → Glue 민감 데이터 기능. 삭제·익명화 → Lambda.

Macie는 탐지만, 마스킹·삭제는 별도 Glue/Lambda 처리 필요
PATTERN 11
워크플로 오케스트레이션 선택

간단한 Lambda 체이닝 → Step Functions. 복잡한 DAG → MWAA(Airflow). 이벤트 기반 트리거 → EventBridge.

Step Functions = 시각적 워크플로, MWAA = 복잡한 의존성+스케줄링 — 용도 구분이 핵심
PATTERN 12
서비스 간 디커플링(느슨한 결합)

1:1 비동기 → SQS. 1:N 팬아웃 → SNS→SQS 구조. 이벤트 라우팅·필터링 → EventBridge.

SNS+SQS 팬아웃 패턴 자주 출제 — SNS가 여러 SQS에 동시 발행하는 아키텍처
PATTERN 13
Athena 쿼리 비용 줄이기

파티셔닝(날짜/지역) + Parquet 포맷 전환. Glue Crawler로 파티션 자동 인식. 쿼리 결과 재사용.

파티션 프루닝 = WHERE절에 파티션 컬럼 조건 → 스캔 데이터 대폭 감소
PATTERN 14
스트림 실시간 이상 탐지

Kinesis → KDA(SQL/Flink) → 이상치 탐지 → SNS 알림 or Lambda 처리. 실시간 집계도 KDA.

KDA 결과를 Kinesis/S3/Lambda로 전달하는 downstream 아키텍처 구조 숙지
PATTERN 15
크로스 계정 데이터 접근

Cross-Account Role Assume + S3 버킷 정책. Lake Formation으로 다른 계정에 테이블·컬럼 단위 공유.

Lake Formation = 정밀한 크로스 계정 데이터 거버넌스 — 컬럼 단위 공유 가능
PATTERN 16
RDS 고가용성 vs 성능 확장

장애 대응(HA) → Multi-AZ(자동 페일오버). 읽기 부하 분산(성능) → Read Replica. Aurora Global → 글로벌 DR.

Multi-AZ = 가용성 목적, Read Replica = 성능 목적 — 혼동은 시험 단골 함정
PATTERN 17
VPC 네트워크 보안 설계

인터넷 없이 AWS 서비스 접근 → VPC Endpoint. S3·DynamoDB → Gateway Endpoint(무료). 나머지 → Interface Endpoint.

VPC Endpoint = 인터넷 없이 AWS 서비스 직접 접근 → 보안+데이터 전송 비용 이점
PATTERN 18
데이터 품질 관리

Glue Data Quality로 스키마·값 검증 규칙. CloudWatch + Lambda로 이상 레코드 알림. DataBrew로 데이터 프로파일링.

Glue Data Quality = ETL 내 품질 게이트 역할 — 불량 데이터를 파이프라인에서 사전 차단
PATTERN 19
앱 로그 수집 파이프라인

앱 → Firehose → S3 → Athena(장기 분석). 또는 앱 → CW Logs → Firehose → OpenSearch(실시간 검색).

실시간 검색·시각화 → OpenSearch, 장기 SQL 분석 → S3+Athena — 목적에 따라 선택
PATTERN 20
CDC 변경 데이터 캡처

RDS/Aurora → DMS CDC → Kinesis → S3/Redshift. DynamoDB 변경 → DynamoDB Streams → Lambda.

CDC = DB 변경 내용만 추출 — 전체 테이블 복사 없이 실시간 동기화 가능
PATTERN 21
서버리스 아키텍처 최적 설계

S3 + Glue(서버리스) + Athena + QuickSight. Lambda + Firehose + S3. "운영 오버헤드 최소화" = 서버리스 조합.

Redshift Serverless, Glue Serverless도 선택지 — "관리 없이" 키워드 시 서버리스 우선
PATTERN 22
대용량 초기 데이터 적재

인터넷 가능·빠름 → DataSync. 인터넷 불안정·느림 → Snowball Edge. 페타바이트 규모 → Snowmobile.

DataSync = 네트워크 전송 최적화, Snowball = 물리 디바이스 운반 — 인터넷 속도가 결정 기준
PATTERN 23
컴플라이언스 감사 추적

API 호출 이력 → CloudTrail. 리소스 설정 변경 → AWS Config. 데이터 접근 로그 → Lake Formation.

CloudTrail = "누가 뭘 했나", Config = "설정이 어떻게 바뀌었나" — 목적 구분 반드시 암기
PATTERN 24
데이터 레이크하우스 구축

S3 + Apache Iceberg/Delta Lake + Athena or Redshift Spectrum. 트랜잭션 지원 + 대규모 분석 동시 가능.

Iceberg = AWS 공식 지원 — Athena, Glue, EMR 모두 Iceberg 테이블 읽기/쓰기 지원
PATTERN 25
QuickSight 대시보드 최적화

Redshift/Athena/S3 → QuickSight. SPICE로 인메모리 캐싱. Row-Level Security로 부서별 데이터 필터링.

QuickSight Q = 자연어로 데이터 질의(ML 기반) — 임원 셀프서비스 분석 시나리오에 등장
PATTERN 26
시계열 IoT 데이터 저장

IoT 센서·서버 메트릭 → Amazon Timestream. 쿼리 최적화 + 자동 TTL. Grafana 연동 시각화.

"시간 기반 데이터" 키워드 → Timestream 우선 고려, 일반 DynamoDB로 저장 시 비효율
PATTERN 27
DB 자격증명 안전 관리

자동 순환(Rotation) 필요 → Secrets Manager. 단순 설정값 → Parameter Store. 하드코딩은 항상 오답.

Secrets Manager는 RDS, Redshift 자동 비밀번호 순환 기본 지원 — 추가 Lambda 불필요
PATTERN 28
Redshift 데이터 공유

Redshift Datasharing으로 다른 클러스터/계정에 라이브 데이터 공유. 복사 없이 읽기 전용 접근.

데이터 복제 없이 공유 → 스토리지 비용 절감 + 항상 최신 데이터 유지
PATTERN 29
파이프라인 장애 모니터링·알림

CloudWatch Alarm → SNS → 이메일/SMS. Glue Job 실패 → EventBridge → SNS. Step Functions → CloudWatch.

공통 패턴: 서비스 → EventBridge/CloudWatch → SNS → 알림 — 이 흐름을 완전 암기
PATTERN 30
S3 성능 최적화

소량 랜덤 접근 → Prefix 분산. 대량 적재 → 멀티파트 업로드(100MB 이상). 원거리 → Transfer Acceleration.

단일 Prefix 한도: 3,500 PUT/5,500 GET per sec — Prefix 분산으로 선형 확장 가능
