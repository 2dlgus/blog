처음 만든 대시보드는 KPI 카드, 도넛 차트, 월별 추세선이 한 화면에 가득했다. 보고 자료로는 보기 좋았지만, 현업 사용자가 화면을 열었을 때 오늘 무엇을 해야 하는지는 보이지 않았다. 신호와 조치 대상 중심으로 다시 구성했다.

문제

숫자와 차트는 많은데 사용자가 할 일, 주의할 점이 바로 보이지 않음

원인

화면을 데이터 종류별로 나눔. 사용자의 다음 행동 기준으로 나누지 않음

해결

탭을 할 일 기준으로 재구성하고, 각 블록은 신호 → 대상 목록 → 근거 순서로 배치

바꾼 원칙

구분변경 전변경 후
탭 기준데이터 종류사용자의 다음 행동
첫 화면전체 KPI 카드 4개지연, 기한 임박 목록
블록 구성모든 콘텐츠를 흰 카드에배경 위 제목, 필요한 곳만 박스
탐색스크롤로 찾기좌측 목차, 현재 위치 표시
목록 길이데이터 양만큼 늘어남규격 고정, 더보기로 펼침
설명 문구화면에 산출 기준 나열별도 문서로 분리, 화면엔 범례만

화면 구성

탭답하는 질문
조치현황지금 처리해야 할 건은 무엇인가
점검대비다음 점검에서 자주 나올 항목은 무엇인가
취약분석반복해서 나오는 곳과 항목은 어디인가
현황통계보고용 전체 숫자

집중관리 대상 기준

"반복해서 나온다"를 화면에 쓰려면 기준이 숫자로 정해져 있어야 한다. 현업과 아래처럼 정했다.

항목정의
재발같은 소분류, 같은 건물에서 최근 2년 안에 서로 다른 점검으로 다시 검출
같은 점검점검명, 시작일, 종료일이 같으면 여러 건이어도 1회
재발률재발 건수 ÷ 기간 내 전체 건수
심각도소분류별 상 3, 중 2, 하 1. 서로 다른 기관 2곳 이상에서 검출되면 +1
집중관리재발률 × 심각도 값이 높은 항목
데이터가 정리되지 않았을 때누적 데이터가 정제되지 않아 의미 있는 결과가 나올지 확신할 수 없었다. 도메인을 새로 만들지 않고 기존 JSON 데이터로 먼저 검증한 뒤, 결과가 나오는 기능부터 적용했다.

메인 화면은 더 단순하게

정식 오픈 때 메인 화면에 "내 조치 현황"을 넣는 안을 검토했다. 서버 집계를 새로 만들어야 했고, 담당자 데이터도 아직 정리되지 않은 상태였다. 메인은 데이터 호출 없는 정적 화면으로 두고, 대시보드는 메뉴로 옮겼다.

  • 메뉴 바로가기, 공지, 문의처만 배치
  • 공지는 날짜순 정렬, 최근 2주 내 글은 새 글 표시, 4건 넘으면 더보기
  • 설정값은 코드 위쪽 객체 하나에 모아 운영자가 직접 수정

점검 목록

  • 첫 화면에서 사용자가 할 일이 보이는가
  • 탭 이름이 데이터 이름이 아니라 질문에 대한 답인가
  • 상단 영역이 본문을 가리지 않을 만큼 낮은가
  • 판정 기준이 현업과 합의된 숫자로 정해져 있는가
  • 화면 설명 문구를 빼도 오해가 없는가
